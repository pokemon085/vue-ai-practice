# 專案規則

本檔僅適用於本專案（`vue-ai-practice`，Metrix SaaS Dashboard UI Kit），不適用於其他專案。
若與全域規則衝突，以本檔為準。

## 1. 技術棧

本專案使用 Vue 3、Vite、TypeScript、SCSS、Vue Router、Pinia。不得擅自更換為其他技術棧。

## 2. 開發前先閱讀

動手前先閱讀相關檔案，沿用現有專案架構、命名與分層。不得任意重建專案或大幅改寫既有程式。

## 3. 依設計稿實作

優先依照 Figma 設計稿實作畫面（版面、間距、字體、顏色、圓角），再逐步加入互動與功能。
不得虛構未提供的設計規格；不確定時先說明假設。

## 4. 元件拆分與 RWD

優先拆出可重複使用的 Vue 元件，避免把整個頁面寫成單一大型元件。所有畫面都必須確認響應式（RWD）行為正常。

## 5. TypeScript 型別

使用明確型別（`type` / `interface`、函式回傳型別），避免使用 `any`。
不得為了讓檢查通過而放寬型別設定或加入型別斷言。

## 6. 狀態管理

Pinia 只用於管理需要跨元件或跨頁面共用的狀態；單一元件內的狀態使用 `ref` 或 `reactive`。
衍生資料優先使用 `computed`，不要把可推導的資料再存一份。

## 7. 程式碼風格

遵守本專案的 ESLint、Prettier 設定與既有程式碼風格（單引號、無分號、2 空格縮排、SCSS 變數與 mixin）。
不得以 `eslint-disable` 或修改設定檔的方式繞過檢查。

## 8. 變更範圍控制

未經確認，不要擅自安裝不必要的套件、不要修改與任務無關的功能、不要更換技術棧。

## 9. 完成後驗證

修改完成後，使用本專案現有的指令驗證，並如實回報結果：

- `npm run lint`
- `npm run format:check`
- `npm run typecheck`
- `npm run build`

不得宣稱未實際執行的檢查已通過；指令失敗時直接提供實際輸出，並列出尚未驗證的項目。
